# RateStats 接入新银行指南（维护版）

## 0. 先给结论

想要“接入新银行站点”，通常**不能做到只改 `url_params.xlsx` 就自动生效**。

因为程序的调用链不只是“URL 从配置读出来”这么简单，还依赖：

1. 代码里是否已经有该银行对应的 **参数 dest**（`argparse` 入口）
2. 代码里是否已经有该银行对应的 **抓取/解析实现**（HTML/PDF/接口结构等）
3. 数据是否能够被 **payload 构建器**写入正确的 DataFrame 列，再进入 **Excel 写入器**回填到模板行列
4. 彩虹表回填时，模板“银行名/数据来源”是否能和新银行行匹配

换句话说：`url_params.xlsx` 可以配置“抓取入口 URL”，但它**驱动不了**程序中缺失的“解析实现/参数签名/映射规则”。

不过，**只改 xlsx 能生效**的场景依然存在（见第 2 节）。

---

## 1. 仅改 xlsx 可行的前提（你可以先自检）

如果你希望“只改 `RateStats_Portable/assets/url_params.xlsx|url_params.json`”就能接入新站点，请确认：

1. 你新增/替换的 key 最终会映射到程序里**已经存在的** `argparse dest`（并且这个 dest 在程序默认参数与白名单中已存在）
2. 该 dest 在 `fetch_and_extract(...)` 的参数签名中已经出现，并且 `fetch_and_extract` 内部会调用对应的抽取函数
3. 抽取函数已经能把抓取结果写进 payload 中已有的数据结构字段（不会因为缺少字段/缺少银行段落导致 payload 为空）
4. 输出时模板/风格逻辑可以识别该银行名字出现在 `数据来源` 字段（样式可能是“匹配不到则无上色”，但至少要能回填正确行）

满足以上条件时，你的 xlsx 改动本质上只是“把 URL 指向某个站点/页面”，代码已有解析能力就能跑通。

## 2.0 快速配置模板（复制粘贴：只改 key 和 url）

下面给一个“维护人员可直接复制粘贴”的示例，用于把新增/替换 URL 写入配置文件。

注意：这个模板只解决“URL 配置能被程序读到并传入抓取参数”的问题；如果程序中**没有**该银行对应的解析实现/参数 dest，那么即使写了 URL 也不会真正接入新站点（见第 2 节与第 3/4 节）。

### 方案 A：改 `RateStats_Portable/assets/url_params.json`

把下面这一行插入到现有 JSON 对象里（`【KEY】` 和 `【URL】` 只需要你替换）：

```json
"【KEY】": "【URL】"
```

其中：
- `【KEY】`：写你在表里使用的“友好中文 key”（需要在 `url_key_aliases.py` 里能映射到某个 argparse dest）
- `【URL】`：写你的目标页面 URL

### 方案 B：改 `RateStats_Portable/assets/url_params.xlsx`

往 xlsx 新增一行即可（列名由程序自动识别：`key/键/参数/param` 与 `url/链接/地址`）：

- `key` 列：`【KEY】`
- `url` 列：`【URL】`

## 2. 接入“新银行站点（需要新解析逻辑）”时，最少要改什么？

你在前面说你想“接入新银行站点，而且结构大概率与现有某个银行高度一致（可复用提取逻辑）”。在这种情况下，维护人员通常需要做的最小改动包括两块：

### 2.1 接入 URL 参数的链路（让 URL 配置真的能喂给程序）

你需要同时检查并在必要时新增以下内容（按文件分）：

1. `RateStats_Portable/assets/url_params.xlsx|url_params.json`
   - 新增一行（或替换原有 key）用于配置你的新银行“促销页/挂牌页”的 URL

2. `RateStats_Portable/url_key_aliases.py`
   - 在 `URL_KEY_ALIASES` 中新增“友好中文 key -> argparse dest”的映射
   - 同时在 `URL_PARAM_DEST_KEYS` 中把 dest 加入白名单（否则 loader 会忽略/不写回）

3. `RateStats_Portable/url_defaults.py`
   - 为新增 dest 补一个默认 URL（否则即使 argparse/白名单允许，也没有“内置默认值”用于覆盖逻辑判断）

4. `RateStats_Portable/bank_cli_parser.py`
   - 给新增 dest 增加 `p.add_argument("--xxx-url", ...)` 以让 argparse 接到该参数

5. `RateStats_Portable/bank_cli_fetch_params.py`
   - 在 `build_fetch_and_extract_inputs(args)` 里把 argparse 的新参数映射成 `fetch_and_extract(...)` 的对应入参

> 说明：这部分决定“配置能否走到抓取函数参数上”。

### 2.2 接入抓取/解析实现（让程序真正理解新银行页面）

程序里真正做“抓取+解析+构建 payload”的入口在主目录的抓取模块中：

- `bank_fetch_and_extract.py`（主目录）
- 解析函数位于：`bank_extractors/impl.py`（主目录）

在 portable 里运行 `RateStats_Portable/bank_all_promo_rates.py` 时，会显式把主目录加入 `sys.path`，从而导入主目录的 `bank_fetch_and_extract.py`：

- `RateStats_Portable/bank_all_promo_rates.py`
  - 顶部附近有：`sys.path.insert(...)`
  - 然后：`from bank_fetch_and_extract import fetch_and_extract`

因此接入新银行站点时，维护人员通常需要：

1. 在 `bank_extractors/impl.py` 中新增一个 `extract_*` 函数
   - 命名建议沿用现有风格：`extract_<银行名>_<promo/board>` 或 `extract_<银行名>_board_pdf/json`
   - 函数内部实现应把解析结果归一成程序期待的 payload 字段结构（DataFrame 列键）

2. 在 `bank_fetch_and_extract.py` 中把这个 `extract_*` 函数接进来
   - 即：当传入你的新 dest（URL 参数）非空时，调用对应 `extract_*`
   - 然后把结果合并进 payload（把新的银行段落写到 payload 对应键上）

3. 若新银行在“输出 Excel 行/列”方面也需要差异化
   - 检查：`bank_excel_data_builder.py` 是否需要把 payload 字段映射/补齐
   - 检查：`bank_excel_template_writer.py` 是否需要额外 sheet/过滤规则

> 说明：这部分决定“新银行解析能力是否存在以及是否能进入 Excel 回填”。

## 3. 需要新增文档的“维护人员操作清单”（不写代码版）

下面是一份维护人员可以逐条勾选的清单：

1. 你要接入的 URL 类型是什么？
   - 是促销页（用于“新元定存促销/外币定存促销”）？
   - 还是挂牌页（用于“新元挂牌利率/外币挂牌利率按币种拆 sheet”）？

2. 你要接入的新银行能否复用现有某个解析器？
   - 能复用：优先复制并小幅改动现有 `extract_*` 的解析规则与字符串标签
   - 不能复用：需要新增解析逻辑，并保证输出 payload 结构兼容

3. URL 配置能否走到 fetch_and_extract？
   - 在 `RateStats_Portable/url_key_aliases.py` 新增友好 key -> dest 映射
   - 在 `RateStats_Portable/url_key_aliases.py` 把 dest 加入 `URL_PARAM_DEST_KEYS`
   - 在 `RateStats_Portable/url_defaults.py` 增加 dest 默认值
   - 在 `RateStats_Portable/bank_cli_parser.py` 新增 argparse 参数
   - 在 `RateStats_Portable/bank_cli_fetch_params.py` 把 dest 映射到 `fetch_and_extract` 入参

4. 抓取解析能否产出 payload？
   - 在主目录 `bank_extractors/impl.py` 新增 `extract_*`
   - 在主目录 `bank_fetch_and_extract.py` 接入对该 URL dest 的调用

5. Excel 回填能否落到模板的正确行/列？
   - `bank_excel_data_builder.py`：字段重命名/列顺序/缺省补齐是否符合模板
   - `bank_excel_template_writer.py`：sheet 创建/过滤规则是否覆盖新银行段落

6. 彩虹表回填（如果你也关心）是否能匹配？
   - `generate_rainbow_from_bank.py` 里银行名/数据来源字段匹配逻辑需能识别新银行

## 5. 你接入新银行时我建议你补充的信息（用于后续维护）

由于维护人员无法直接看到你的页面结构差异，建议你每次新增银行时附上以下信息（尽量用最少材料）：

1. 促销页/挂牌页的 HTML 片段（或接口 JSON 字段名）
2. 对应页面里“银行名/币种/金额区间/tenor”的位置与字段名
3. 你希望它最终出现在 MarketRateData 哪个 sheet/哪种行（促销还是挂牌）

有了这些，后续维护人员能更快把 `extract_*` 写成可复用的解析器。
